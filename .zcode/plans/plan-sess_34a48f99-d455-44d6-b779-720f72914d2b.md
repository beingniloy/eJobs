## Location-Based Job Search — Fix Plan

### Problem
Homepage sends `division`, `district`, `upozilla` URL params to `/jobs`, but:
- `JobsListClient.tsx` ignores them (only reads `keyword`)
- Jobs table has no `division`/`district`/`upazila` columns (only free-text `location`)
- Backend search only does `location LIKE '%query%'`
- No location filter UI on jobs page
- Job posting form has no structured location dropdowns

### Fix — 7 files, ~300 lines

| # | File | Change |
|---|------|--------|
| 1 | **New migration** `add_location_fields_to_jobs_table.php` | Add `division`, `district`, `upazila` (string, nullable) to `jobs` |
| 2 | `backend/app/Models/Job.php` | Add 3 fields to `$fillable` |
| 3 | `backend/app/Http/Controllers/Api/EmployerController.php` | Accept + save `division`, `district`, `upazila` in `storeJob()` |
| 4 | `backend/app/Http/Controllers/Api/JobController.php` | Filter by `division`, `district`, `upazila` params in `index()` |
| 5 | `frontend/src/app/(employer)/employer/post-job/page.tsx` | Replace plain text location with 3 cascading dropdowns (Division → District → Upazila) from `bd-data.ts` |
| 6 | `frontend/src/app/jobs/JobsListClient.tsx` | Read URL params, add location filter sidebar, send params to API |
| 7 | `frontend/src/app/page.tsx` | Replace inline location data with imports from `bd-data.ts` |

### Data Flow After Fix
```
Homepage → /jobs?division=Dhaka&district=Dhaka&upazila=Mirpur
  → JobsListClient reads params → sends to API
  → Backend: WHERE division=? AND district=? AND upazila=?
  → Filtered results

Employer posts → Division/District/Upazila dropdowns
  → Saved to jobs table + backward-compat location string
```
